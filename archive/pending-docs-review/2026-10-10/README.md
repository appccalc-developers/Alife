# 待确认的历史文档

这里保存 2026-10-10 Docs 审查中移出的 99 个文件。它们尚未删除，也尚未由用户永久确认归档；当前开发和新 Church App 生成不使用这里的内容作为指导。

查看 [逐目录、逐文件清单](../../../docs/governance/DOCUMENT-USAGE.zh-CN.md) 和 [原路径／现路径／原因／原始哈希](../../../docs/governance/document-register.json)。`docs/` 下保持原目录层次，所有移动原件字节保持不变。历史 Markdown 的相对链接保留原路径语境，调查时按机器清单找到实际目标；不要执行旧脚本或把历史测试结果当作当前验证。

仓库 `.gitattributes` 对这里使用 `-text`，保留原件的换行和原始哈希；不要对历史原件做格式化或换行转换。

`docs/Communication/` 与 `docs/VibeCoding/` 原为被 Git 忽略的本地材料，移动后仍保持忽略。清单只登记用途和路径，不复制其正文、凭据或诊断响应。

公开仓库检出不包含这些已忽略原件。审计会明确报告缺席数量、检查忽略规则，并核对本机实际存在原件的哈希；不会将缺席的本地材料误称为已发布或已验证内容。

有日期的 Event 实施历史和权限验证记录仍能通过现行文档中的“历史证据”链接查阅，但业务规则由当前 Event 核心、主题、模块、JSON 和状态文档维护。

确认时可分别选择：保留历史归档；某项内容确实仍需使用，归整进当前权威来源；或明确授权删除。未确认前不执行删除。旧 Issue 候选、原始愿景与当前契约是否有遗漏，由工作台账 DOCS-RECONCILE 核对。
