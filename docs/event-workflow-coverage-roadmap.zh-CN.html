ALIFE · 活动管理研究与演进建议

活动流程覆盖现状与未来设计

这份文档说明当前活动功能究竟覆盖到哪里、创建页面与流程页面怎样衔接、审批节点实际审批什么，并提出未来的产品目标、理想使用流程、核心能力、优化优先级与分阶段落地路线。

讨论稿 更新日期：2026-08-21 代码基线：061ded7 范围：活动创建、筹备、审批、执行与跟进
1

先说结论

页面上看到的“三种”，不是三种活动类型。

当前是什么 一个通用的活动流程机制，加上“轻量创建、营会、外展”三种筹备选择。营会和外展才是内置流程模板，轻量创建表示不生成额外筹备任务。
当前覆盖到哪里 已覆盖活动资料、双语内容、草稿找回、AI 整理、通知、报名基础、海报、可见范围、RAM、人工作出确认、线性阶段、审批点和产出物状态。
未来应该怎样 产品上提供多个活动流程包；开发上保留一个稳定核心。营会、外展、培训、常规聚会、敬拜、儿童青少年等分别配置流程和专用模块。
审批目前怎样 RAM 已经有独立审计权限；其他审批点目前只是由组长或副组长操作的状态标记，还没有独立审批人、审批意见和禁止自审规则。
对截图中建议的判断： “不要让一套固定流程硬套所有活动”是正确的；但不建议复制多套互不相干的流程引擎。更稳妥的方式是“一套共享核心 + 多个活动流程包 + 可插拔专用模块”。这样既能覆盖不同活动，也不会把权限、隐私、审批、通知和审计逻辑复制很多遍。
2

当前实际覆盖的活动流程

以下是现在系统已经形成的完整链路，不等于每个活动都需要使用所有环节。

  1. 开始或找回草稿新建活动，或继续上次未提交的活动草稿。
  2. 选择筹备方式轻量创建、营会、外展，或小组自定义模板。
  3. 填写活动资料标题、说明、时间、地点、对象、人数、费用、联系人和可见范围。
  4. 准备活动海报上传现有海报、读取参考海报，或生成需要人工采用的 AI 海报草案。
  5. AI 协助整理整理已提供的事实、指出缺失资料；不能替代负责人作安全或身份确认。
  6. 提交活动通知保存活动资料，形成通知与报名所需的活动记录。
  7. 完成 RAM 审核按基本信息、风险、联系人、人工确认处理，并由有权限的人批准。
  8. 执行筹备与跟进如果选择了流程模板，保存后生成阶段、审批点和产出物，并记录完成情况。
当前容易造成误解的地方： “活动创建四步”和“模板内的筹备阶段”属于两个层次。前者负责把活动建立并通过 RAM；后者负责活动建立后的具体筹备与执行。未来界面应继续明确区分“创建活动”和“执行流程”。
2A

两个页面怎样衔接

当前不是在一个页面里完成全部工作，而是先创建活动，再到活动详情执行筹备流程。

页面一

活动创建／编辑页面

解决“活动是什么、谁能看、能否发布”的问题。

  1. 选择所属小组和筹备方式。
  2. 填写标题、说明、时间、地点、对象、人数、费用与联系人。
  3. 设置小组内、教会内或公开可见。
  4. 上传、读取或生成活动海报。
  5. 让 AI 整理事实并人工核对。
  6. 提交活动通知，建立活动记录。
  7. 填写并提交 RAM，等待活动审计人员批准。
页面二

活动详情里的“活动工作流”

解决“活动建立以后，团队怎样完成筹备任务”的问题。

  1. 查看所选模板、必需阶段完成数量和当前阶段。
  2. 点击顶部阶段卡，跳到对应阶段。
  3. 处理该阶段的计划、预算、名单、报告等产出物。
  4. 开始阶段、提交审批、完成或重新打开阶段。
  5. RAM 阶段不在这里直接操作，而是返回活动编辑页面处理。
创建页面的结果

保存活动时，系统根据选中的模板生成一份不可被未来模板修改影响的流程快照、阶段和产出物占位。

→
流程页面接手执行

团队在活动详情中推进筹备状态；如果选择轻量创建，则没有额外阶段，活动仍保留通知、报名和 RAM。

不要混淆： 活动可见范围不是流程审批。选择“公开可见”只表示 RAM 批准后允许公开展示；真正令活动进入可见状态的是 RAM 批准，不是普通阶段的“完成”按钮。
2B

审批节点到底审批什么

先沿着当前营会、外展、RAM 和自定义流程图看审批点，再解释每个节点的操作者与系统约束。

普通执行阶段 普通审批标记 有独立权限的 RAM 审批

审批类型、角色和系统结果总表

审批对象 提交人 当前批准人 系统实际检查 批准后的结果
RAM 风险评估 所属小组的组长或副组长 拥有 admin.events.audit 权限的活动审计人员 RAM 必填内容、风险、紧急联系人和人工确认是否完整；只允许批准“等待审核”的 RAM RAM 变为已批准；对应流程阶段和 RAM 产出物同步完成；活动按可见范围展示并通知小组成员
普通产出物 所属小组的组长或副组长 同样是组长或副组长；目前可以由同一人完成 只检查状态和文件可见级别是否一致；当前不要求必须附文件，也没有审批意见 产出物由“已提交”变为“已批准”，允许所在阶段满足完成条件
普通阶段审批点 所属小组的组长或副组长 同样是组长或副组长；没有指定审批角色 完成阶段时，所有必需产出物必须已批准；不检查提交人与批准人是否不同 阶段变为“已完成”，流程进度增加；全部必需阶段完成后流程结束
活动通知／公开发布 所属小组的组长或副组长 目前没有独立文案或发布审批人 活动资料完整，并且 RAM 获得批准 活动依据小组、教会或公开范围被相应人员看到

三个状态变化要分开理解

普通产出物：计划、预算、名单、报告等

草稿→ 标记已提交 → 已提交→ 批准 → 已批准→ 退回草稿 → 草稿

当前只有“草稿、已提交、已批准”三种状态，没有“退回修改”理由或拒绝意见。页面只允许已批准产出物退回草稿。

普通流程阶段

未开始→ 开始 → 进行中→ 请求审批 → 等待审批→ 完成阶段 → 已完成→ 重新打开 → 进行中

“请求审批”目前只是把状态改成等待审批。系统没有独立的“批准阶段”按钮；组长或副组长使用“完成阶段”结束该阶段。

RAM 风险审批

草稿→ 组长提交审核 → 等待审核→ 审计人员批准 → 已批准

RAM 保存任何修改时都会回到草稿，并清除此前的提交与批准记录。当前没有“退回并填写意见”按钮。

内置模板中的审批点逐一说明

模板与节点 业务上应当确认什么 当前系统怎样做 当前不足
营会：提案与预算 活动目标、计划和预算是否可行，是否允许进入正式筹备 活动计划与预算两个必需产出物先标记已批准，再完成阶段 没有指定牧者或财务审批人，也没有金额、预算明细和审批意见
营会／外展：风险评估 风险、控制措施、负责人、紧急联系人和外出安全是否可信且完整 通过独立 RAM 页面提交，由活动审计权限人员批准 当前缺少退回原因和复审意见，但这是目前最接近真正审批的节点
营会：结算与跟进 财务是否结清、活动回顾是否完成、后续事项是否有人负责 财务报告和活动回顾为必需产出物；批准后完成阶段 没有财务角色、金额核对、差异说明或跟进完成证明
外展：目标与团队 外展目标、方式、团队和负责人是否合适 外展计划与团队名单为必需产出物；批准后完成阶段 没有事工负责人或牧者专属审批，也没有团队资格规则
外展：新朋友跟进 敏感联系资料是否被妥善保管，跟进是否得到同意并明确分工 新朋友名单、跟进分工和活动回顾进入产出物状态；前两项仅管理者可见 没有同意有效期、资料删除期限、交接记录或隐私负责人审批
自定义模板：任意审批点 由创建者填写的阶段名称决定，系统本身不知道审批内容 显示“需要审批”，允许进入等待审批并由组长／副组长完成 不能设置审批说明、必需材料、指定角色或审批条件，因此目前更像提醒标记
必须明确的现状限制： 普通审批点目前不具备职责分离。请求审批的人可以继续批准产出物并完成阶段；“需要审批”的阶段也可以不经过等待审批状态而直接完成，只要必需产出物已经显示为批准。产出物没有附文件时也能变成已批准。因此，除 RAM 外，现有审批徽标只能视为团队进度记录，不能视为正式的财务、安全、隐私或事工授权证明。
未来合格的审批节点应当包含： 审批事项说明、必需证据、提交角色、审批角色、禁止自审、批准／退回修改／拒绝、审批意见、时间记录、提醒和审计日志；不同节点应分别支持事工负责人、财务、活动审计、隐私负责人或教会管理员。
2C

当前页面操作手册

下面按真实按钮和页面状态说明怎样操作，不把尚未实现的功能写成可用功能。

一、新建活动并生成流程

  1. 进入活动创建页面，先确认所属小组。
  2. 在顶部选择“轻量创建、营会、外展”或已保存的自定义模板。
  3. 选中模板后，在下方确认阶段顺序和带盾牌标记的审批点。
  4. 完成活动资料、可见范围、联系人和海报；AI 协助可选。
  5. 点击 提交并进入 RAM。只有保存活动后，模板才会生成实际阶段和任务。
  6. 如果选轻量创建，活动仍可继续完成通知、报名和 RAM，但活动详情不会出现额外筹备阶段。

二、填写和提交 RAM

  1. 依次完成“基本信息、风险、联系人、人工确认”四个分区。
  2. 修改内容会自动保存；顶部显示完成比例和最后保存状态。
  3. 资料不完整时点击底部按钮，页面会展开第一个未完成分区并定位到第一个无效字段。
  4. 组长核实姓名、电话、资质、车辆和安全事实，勾选人工确认。
  5. 点击 提交审核，RAM 进入等待审核。
  6. 拥有活动审计权限的人在同一 RAM 页面点击 批准 RAM。

三、从活动详情进入流程

  1. 打开已保存活动的详情页，找到“活动工作流”。
  2. 顶部显示模板名称、版本、必需步骤完成数量和总体状态。
  3. 点击横向阶段卡，页面跳到对应阶段；蓝色卡表示当前优先阶段，绿色卡表示已完成。
  4. 如果旧活动还没有流程，组长／副组长可以在这里选择模板并点击 采用此工作流。
  5. 活动一旦已有流程，当前页面不能更换成另一个模板。

四、处理普通产出物

  1. 查看产出物是否必需，以及公开、小组可见或管理者私密的可见级别。
  2. 产出物准备好后点击 标记为已提交。
  3. 复核人点击 批准，状态变为已批准。
  4. 发现已批准内容需要重做时，点击 退回草稿。
  5. 如果显示“打开文件”，先打开并核对文件；没有文件按钮时，不能仅凭状态徽标断定材料已经上传。

五、推进普通阶段

  1. 点击 开始，阶段由未开始变为进行中。
  2. 若阶段标记为需要审批，准备完成后点击 请求审批。
  3. 所有必需产出物必须先显示为已批准，否则 完成阶段 不可用。
  4. 复核无误后点击 完成阶段。
  5. 完成后需要继续修改，可点击 重新打开 回到进行中。

六、RAM 阶段怎样操作

  1. 流程页面的 RAM 阶段只显示同步状态，不提供普通阶段按钮。
  2. 点击 打开活动／RAM 编辑器 返回活动编辑页面。
  3. RAM 提交后，流程阶段自动变为等待审批，RAM 产出物变为已提交。
  4. RAM 批准后，流程阶段自动完成，RAM 产出物自动批准。
  5. 再次保存 RAM 修改会撤销原批准并把流程阶段退回进行中。

现有三种筹备方式分别覆盖什么

当前只有两个内置专项模板；自定义模板是第四种能力入口，不是固定活动类型。

轻量创建

已实现

适合聚餐、查经和普通聚会。完成活动资料、通知、报名与 RAM，但不会额外生成一套筹备任务。

适合：准备工作少、负责人清楚、没有复杂跨阶段交付物的活动。

营会流程

6 个阶段
  1. 提案与预算（审批）
  2. 风险评估（审批，连接 RAM）
  3. 报名与缴费
  4. 人员与程序
  5. 营会执行
  6. 结算与跟进（审批）

内置 15 项产出物，包括计划、预算、参加者名单、缴费记录、同工排班、同意书、出席、事故报告和财务报告等。

外展流程

6 个阶段
  1. 目标与团队（审批）
  2. 培训与简报
  3. 风险评估（审批，连接 RAM）
  4. 接触预备
  5. 外展执行
  6. 新朋友跟进（审批）

内置 14 项产出物，特别关注培训、同意、联系资料隐私、新朋友名单与跟进分工。

小组自定义模板

基础版本

组长可以命名模板，添加、删除和排序 1–12 个阶段，并为阶段设置审批点；模板只在本小组内重复使用。

目前不能配置：产出物、RAM 等专用连接、条件分支、并行步骤、角色要求、提醒规则、模板编辑、复制、归档和版本升级。

未来目标：一个核心，多个活动流程包

不是把现在的表单做得更复杂，而是让每类活动获得恰到好处的引导、协作、审批和安全保障。

让每次活动在正确的流程、正确的责任人、充分的依据和合适的可见范围下完成。

这是未来活动管理的北极星目标：简单活动足够快，复杂活动足够安全；负责人随时知道下一步，审批人清楚自己在判断什么，教会也能持续改善流程。

清晰每个人都看得懂当前进度、下一步和阻塞原因
适配不同活动只出现真正需要的阶段、资料和政策
可信重要决定有负责人、有依据、有意见、有记录
可改进模板能复用和升级，旧活动不会被新规则悄悄改变

未来一次活动应当怎样完成

  1. 识别活动先回答“这是什么活动”，不先面对一整套复杂表单。
  2. 推荐方案系统推荐流程包、政策和专用模块，并说明推荐原因。
  3. 确认边界负责人确认角色、时间、对象、可见范围和所需资料。
  4. 协同筹备按阶段分工、设定期限、提交产出物，并清楚看到阻塞项。
  5. 提交审批审批人围绕明确问题和依据作出批准、退回或拒绝决定。
  6. 执行活动使用签到、排班、现场检查和异常记录等按需模块。
  7. 结束复盘完成结算与跟进，沉淀经验，但不自动修改已有模板。
目标定义：未来不是为营会、外展、培训分别复制三套互不相干的系统。使用者看到的是适合不同场景的流程包；底层仍共用权限、隐私、任务、通知、审计和双语能力。这样既能覆盖不同活动，也能控制开发和维护风险。

未来能力结构

共享核心

登录与权限、所属小组、双语资料、草稿、可见范围、AI 人工确认、通知、任务、审计、缓存与隐私。所有活动共用，只维护一份。

活动流程包

为每类活动定义推荐阶段、审批点、必需产出物、角色、提醒规则和适用政策。流程包可以独立升级和版本化。

专用模块

RAM、报名与缴费、签到、同工排班、同意书与监护人、场次与场地、设备检查、新朋友跟进等按需启用。

活动实例快照

每个活动保存创建时所选流程包和版本的快照。以后模板改变，不会偷偷改变正在进行或已经完成的活动。

建议优先形成的流程包

常规聚会

聚餐、查经、祷告会、小组聚会；字段少、快速发布，可根据风险触发 RAM。

营会／退修会

保留现有营会模板，逐步加入住宿、多场次、接送、监护人与结算。

外展／社区接触

保留现有外展模板，加强同意、资料保留、访客交接和后续跟进。

培训／课程

覆盖课次、材料、讲员、报名、出席与完成情况，不强行使用营会字段。

敬拜／大型活动

覆盖程序、排班、场地、设备、彩排、执行台本与多个团队协作。

儿童青少年政策包

作为可叠加政策，加入监护人、健康资料、接送授权、签到签退和安全确认。

关键设计原则： “活动类型”回答这是什么活动；“流程包”回答怎样筹备；“可见范围”回答谁能看到；“政策包”回答必须遵守哪些安全和隐私规则。四者需要分开，不能再由一个模板名称同时承担。

未来六项核心能力

01

引导式创建

  • 先选活动类型，再推荐流程，不用猜模板。
  • 只显示当前活动需要的字段和政策问题。
  • 选择前可预览阶段、审批、预计工作量与适用范围。
02

可信审批中心

  • 每个审批点明确审批事项、依据、审批人和通过条件。
  • 支持提交、批准、退回修改、拒绝、意见和通知。
  • 关键事项禁止提交人自审，并完整保留决定记录。
03

可视化协作

  • 用角色泳道、阶段卡片和依赖关系呈现流程。
  • 清楚显示负责人、期限、下一动作、阻塞和逾期。
  • 任务、资料、审批和历史围绕同一活动组织。
04

流程治理

  • 区分平台、教会和小组模板的维护权限。
  • 支持复制、编辑、停用、版本升级和活动快照。
  • 规则变化可追踪、可解释，并提供安全回退方案。
05

可插拔业务模块

  • RAM、报名缴费、签到、排班、同意书按需组合。
  • 进一步支持场次场地、设备、交通、住宿和跟进。
  • 敏感资料按角色和用途控制，不随流程公开传播。
06

受控的 AI 协助

  • 根据当前阶段提示缺失信息、风险和下一步。
  • 帮助整理资料、形成摘要和建议，不编造安全事实。
  • AI 不代替审批、不自动发布，最终决定始终由人确认。

未来流程页面应该长什么样

负责人首页

先给结论，再给细节。

  • 当前完成度与是否可以进入下一阶段
  • 今天最需要处理的下一动作
  • 阻塞原因、逾期事项和待他人处理项目
  • 活动何时达到“可报名、可执行、可结束”

活动流程中心

这是主要工作页面，不再只是纵向排列的一长串表单。

  • 顶部显示阶段地图、关键里程碑和整体准备度
  • 中部用角色泳道表达谁负责、谁配合、谁审批
  • 每个阶段集中展示任务、资料、审批、风险和历史
  • 右侧持续显示“下一步”和进入下一阶段的条件

审批人工作台

审批不是点一个勾，而是完成一次有依据的判断。

  • 待审批列表和响应期限
  • 本次到底要判断的问题
  • 负责人提交的材料、风险和变更摘要
  • 批准、退回、拒绝及必须填写的决定意见

优化优先级

P0 · 先建立信任

让审批真正成立

明确事项、依据、审批角色和通过条件；补齐提交、退回、拒绝、意见、通知与审计；关键节点禁止自审。

完成信号

任何人打开审批记录，都能回答“谁在何时、根据什么、做了什么决定，以及下一步是什么”。

P1 · 扩大真实覆盖

建立活动类型和流程包

先覆盖常规聚会、营会、外展和培训；补齐模板版本、活动快照、政策触发和负责人／期限设置。

完成信号

大多数常见活动不再借用不合适的营会或外展流程，简单活动也不会被复杂字段拖累。

P2 · 提升协作效率

补齐专用模块和协作能力

按优先级加入报名缴费、排班签到、同意书、多场次等模块，再处理并行任务、跨小组协作、变更和异常。

完成信号

负责人无需在线下表格和聊天记录中反复对账，系统能清楚呈现依赖、阻塞和责任归属。

P3 · 持续优化

用数据和 AI 改善流程

分析耗时、退回与阻塞，比较模板版本；AI 根据阶段提出建议、整理依据和预警，但不代替人的决定。

完成信号

流程改动能够说明依据并验证成效；AI 的每项建议都可检查、可修改、可忽略。

如何衡量目标是否达成

创建是否清楚

观察创建完成率、平均用时、中途退出位置，以及选错流程后重新创建的比例。

审批是否有效

观察首次通过率、平均响应时间、退回是否有明确原因，以及自审或无依据审批是否归零。

执行是否可预期

观察阶段按时完成率、逾期任务、长期阻塞项，以及活动开始前关键条件的完成度。

流程是否可复用

观察流程包复用率、各版本使用情况、重复自建模板数量和旧流程淘汰情况。

安全是否可信

检查越权访问、隐私泄露、可见范围错误和关键审计缺失；这些事件的目标应始终是零。

AI 是否真正有价值

观察建议采纳率、人工修改率和节省时间；自动审批与未经确认发布的数量必须保持为零。

指标使用原则：先用当前产品建立真实基线，再为各阶段设定数值目标。现阶段不应凭空承诺“提升多少百分比”，而应先确保数据定义、采集方式和业务含义一致。
7

建议实施路线

先让现有审批和页面值得信任，再扩大活动覆盖；每一阶段都能单独交付、验证和回退。

第一优先不是继续增加模板数量。 当前最重要的是把“下一步是什么、要交什么、谁来审批、凭什么通过”讲清楚。这个基础没有建立，模板越多，使用者面对的困惑和维护成本也会越多。
第一阶段 · 可信可用

先修好现有流程体验和审批

  • 重构流程首页：突出下一步、阻塞项、负责人和进入下一阶段的条件。
  • 统一审批状态和操作，加入提交、退回、拒绝、意见、通知与决定记录。
  • 重要审批分离提交人与审批人；产出物必须提供规定的依据。
  • 补齐负责人和期限的设置入口，并保持海报、RAM、可见范围等现有能力独立可用。

交付判断：营会和外展能够完整走通，参与者无需口头解释也能知道如何操作。

第二阶段 · 覆盖扩展

建立活动类型、流程包和模板治理

  • 增加独立的“活动类型／活动族”，不再用流程模板代替活动类型。
  • 优先覆盖常规聚会、营会、外展和培训，并允许选择轻量创建。
  • 支持预览流程、复制模板、编辑新版本、停用旧版本和保留活动快照。
  • 根据参与者、地点、年龄、交通等事实触发 RAM 或儿童安全等政策。

交付判断：四类活动各自拥有合适流程，模板变更不会影响进行中或已完成活动。

第三阶段 · 协作深化

加入高价值专用模块

  • 根据业务价值选择首批模块，而不是一次开发全部功能。
  • 优先评估报名缴费、签到排班、监护人同意和多场次管理。
  • 逐步支持并行任务、跨小组协作、变更申请、异常处理和升级提醒。
  • 将敏感健康、儿童和访客资料限制在真正需要的角色范围内。

交付判断：至少两个高频线下工具被系统替代，且权限和隐私验证通过。

第四阶段 · 智能改进

用数据和 AI 优化，而不是代替人

  • 建立流程耗时、退回、阻塞、逾期和模板复用的管理视图。
  • 用版本对比验证流程调整是否真的减少工作或提高安全。
  • AI 根据当前阶段整理资料、提醒缺口、预判阻塞并解释推荐原因。
  • 继续坚持人工批准和人工发布，不把 AI 建议当作事实或授权。

交付判断：每次流程优化都有可核对的依据，AI 结果始终可审查、可修改、可拒绝。

持续原则 · 安全演进

每一阶段都必须守住的边界

  • 先小范围试用，再逐步推广；保留旧流程的查看和回退能力。
  • 服务端持续校验所属小组、角色、可见范围和审批权限。
  • 双语资料、已有活动和现有 API 保持兼容，不用重建历史数据。
  • 每次发布都有验收场景、权限测试、隐私检查和清晰变更说明。
最终目标 · 可判断的成功

负责人不再“研究系统”才能办活动

  • 负责人先选“这是什么活动”，系统再推荐“怎样筹备”。
  • 每个参与者只看到与自己相关的任务、资料和决定。
  • 审批有明确问题与依据，活动是否准备就绪可以被解释和追溯。
  • 流程可以复用和持续改善，但不会牺牲隐私、人工判断或历史稳定性。
8

进入开发前需要业务方确认的问题

这些答案会决定第一轮流程包的边界，避免再次用一个模板猜所有活动。

  1. 首批必须覆盖哪四类活动？ 建议从常规聚会、营会、外展、培训开始。
  2. 哪些活动一定需要完整 RAM，哪些只需简化风险确认？ 应由活动事实和政策触发，而不是只看模板名称。
  3. 儿童青少年要求是独立活动类型，还是叠加到任何活动上的政策？ 建议作为可叠加政策。
  4. 模板由谁维护？ 需要确定平台、教会管理员和小组组长各自能创建、修改或停用什么。
  5. 报名、缴费、排班、签到和跟进，第一阶段最需要哪两个专用模块？ 不宜同时开发全部模块。
  6. 探访关怀是否纳入活动？ 因为隐私和持续个案管理要求不同，建议先作为独立模块评估。
