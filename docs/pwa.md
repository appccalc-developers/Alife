# PWA Support - Alife Church

This document covers the Progressive Web App (PWA) implementation for the Alife Church frontend, including iOS/iPhone considerations.

## Overview

The app is configured as a standalone PWA so users can install it to their home screen on both Android and iOS. Key PWA features include:

| Feature | Status |
|---|---|
| Web App Manifest | Yes, `/manifest.json` |
| Service Worker | Yes, generated as `/sw.js` by `vite-plugin-pwa` |
| Offline shell | Partial; built assets are cached, API data is not replayed from the service worker |
| Home screen install | Android install support + iOS "Add to Home Screen" |
| Splash screens | Apple touch startup images for modern iPhones and iPads |
| App icons | 72-512 px, including `apple-touch-icon` tags |

## Manifest

The manifest (`public/manifest.json`) uses:

- **name**: `Alife Church`
- **short_name**: `Alife`
- **display**: `standalone`
- **background_color / theme_color**: `#003366`
- **orientation**: `portrait-primary`
- **lang**: `en-NZ`

Icons list both `any` and `maskable` purpose entries so Android adaptive icons work correctly while remaining backward-compatible with browsers that do not support `purpose`.

## Service Worker

The service worker is generated by `vite-plugin-pwa` from `vite.config.ts` and emitted as `/sw.js` at build time. Registration is explicit through `src/registerSW.ts` using `virtual:pwa-register`.

The Workbox runtime configuration currently:

1. Cleans outdated caches and claims clients after activation.
2. Uses `NetworkFirst` for same-origin navigations, documents, scripts, and styles.
3. Uses `StaleWhileRevalidate` for same-origin images and fonts.
4. Uses `StaleWhileRevalidate` for supported external image URLs.
5. Avoids runtime replay of `/api/*` responses because auth, permissions, HTTP validators, and IndexedDB-backed caches handle application data freshness.
6. Uses a catch-all same-origin runtime cache only for non-API requests.

### Updating Cache Behavior

Update the `VitePWA({ workbox: ... })` block in `vite.config.ts`. There is no checked-in `public/sw.js` cache version to edit.

## iOS / iPhone Compatibility

### Meta Tags

`index.html` includes:

| Tag | Purpose |
|---|---|
| `apple-mobile-web-app-capable` | Enables standalone mode on iOS |
| `mobile-web-app-capable` | Enables standalone mode where supported |
| `apple-mobile-web-app-status-bar-style` | `black-translucent` blends with the app theme |
| `apple-mobile-web-app-title` | Name shown under the home screen icon |
| `apple-touch-icon` | Home screen icon for older iOS that ignores the manifest |
| `apple-touch-startup-image` | Splash screen while the app loads |
| `viewport-fit=cover` | Extends content behind the notch/home indicator |

### Safe Area Insets

CSS `env(safe-area-inset-*)` padding is applied so content does not overlap the notch or home indicator on edge-to-edge iPhones.

### Overscroll Bounce

`overscroll-behavior-y: none` on `<body>` prevents rubber-band bounce in standalone mode.

## Known iOS Limitations And Workarounds

### Service Worker Support

- **iOS < 11.3**: No service worker support. `registerSW.ts` checks for `navigator.serviceWorker` before registration.
- **iOS 11.3-13**: Service workers are supported but cache storage is limited and may be purged after inactivity.

### No Install Prompt

iOS Safari does not fire the `beforeinstallprompt` event. Users must manually tap **Share -> Add to Home Screen**. Consider adding an in-app banner that detects iOS Safari and shows instructions.

```js
const isIos = /iphone|ipad|ipod/i.test(navigator.userAgent);
const isStandalone = window.matchMedia('(display-mode: standalone)').matches
  || ('standalone' in navigator && navigator.standalone);

if (isIos && !isStandalone) {
  // Show "Add to Home Screen" instructions.
}
```

### Push Notifications

- Push notifications via the Web Push API are not supported on iOS < 16.4.
- On iOS 16.4+, push is only available after the user adds the app to their home screen.

### Background Sync

`SyncManager` is not available on iOS Safari. Retry failed requests when the app regains connectivity instead of relying on background sync.

### Fixed Positioning Quirks

When the iOS keyboard opens, `position: fixed` elements can shift. Prefer sticky positioning for input-adjacent controls or listen for `visualViewport` resize events.
