# Alife 教会事工平台说明书

## 1. 文件用途

本说明书供以下同工参考：

- 教会执事会：了解本系统能支持哪些教会事工、适合怎样的管理方式、上线后可带来的实际帮助。
- 网站维护与内容编制同工：了解如何整理、编写、发布和更新网站内容。
- 小组长、区牧或行政同工：了解各自可使用的功能边界与建议流程。

Alife 不是单一的资讯网站，而是一个以教会生活运作为核心的线上平台。它将会员登录、群组管理、页面发布、活动报名、通知消息、讲道整理与部分行政流程整合在同一个系统中，并可在电脑与手机上使用。

## 2. 平台的主要作用

Alife 的目标，是把教会常见但分散的事务集中管理，让信息发布更一致，让同工协作更顺畅，让会友更容易找到需要的内容。

它主要解决以下几类需要：

1. 帮助新朋友和会友顺利进入教会线上平台，并维持稳定、安全的登录体验。
2. 帮助小组与事工团队处理成员加入、审批、角色分工与日常沟通入口。
3. 帮助教会持续发布页面内容，例如聚会信息、课程介绍、事工说明、活动页面与常见说明。
4. 帮助同工整理活动报名、活动后回顾、通知回复，以及与讲道相关的资讯展示。
5. 帮助管理同工以较少的技术负担维护网站与内容结构。

## 3. 主要功能介绍

### 3.1 会员登录与身份管理

- 支持以 LINE 登录进入系统。
- 系统会保存会员的基本资料与所属群组关系。
- 不同身份可看到不同功能，减少误操作与无关信息干扰。
- 系统会在每次操作时重新确认权限，避免因为角色变更而出现权限过期问题。

对执事会而言，这代表平台比较适合承载真实教会成员关系，而不只是开放式公告栏。

### 3.2 群组与小组管理

- 教会可有主群组与下属小组的层级结构。
- 会员可申请加入群组，领袖或副领袖可以审批、拒绝、调整角色或移除成员。
- 群组页面与管理页面分开，日常浏览与后台管理不会混在一起。

这项设计特别适合教会的小组牧养、课程班级、事工团队与阶段性服事编组。

### 3.3 页面与内容发布

- 支持全站页面与群组页面。
- 页面可使用中英文双语标题与摘要。
- 页面采用区块式编排，可逐段建立内容，而不是一次编辑整页原始代码。
- 页面可设定三种可见状态：
  - `Draft`：草稿，仅编者或有权限者内部编辑。
  - `Group`：群组可见，适合给已加入该群组的成员阅读。
  - `Public`：公开，适合对全教会或对外访客发布。

这使平台同时能承担“内部通知板”和“对外教会网站页面”的角色。

### 3.4 活动与报名流程

- 群组可建立活动页面与活动资料。
- 会员可以进行活动报名。
- 系统支持以 AI 对话式流程辅助整理活动规划、报名内容与活动回顾草稿。
- 最终报名和回顾仍由使用者确认后，通过后端 API 保存，避免未经确认的 AI 内容直接成为正式记录。

若教会未来要推动退修会、课程报名、短宣或专题活动，这个模块有很高的延伸价值。

### 3.5 通知消息与回复

- 系统已支持面向会员的通知消息。
- 会员可以将通知标记为已读。
- 部分流程可以收集结构化回复，减少只依赖零散聊天记录的情况。

这适合用于审批提醒、后续跟进和轻量行政协调，让同工较容易追踪事情是否已经处理。

### 3.6 讲道与信息整理

- 系统可呈现讲道列表。
- 管理员可同步讲道资料，减少重复手工整理。
- 适合作为主日信息、专题系列、装备课程的统一入口。

### 3.7 手机与电脑都可使用

- 前端为手机友善的网页应用。
- 会友不需要另外安装复杂软件，也能在手机上方便浏览与操作。
- 适合教会日常通知、页面阅读与活动参与。

## 4. 适合的服事分工

建议教会按以下方式理解和使用本平台：

### 4.1 执事会或核心行政团队

适合负责：

- 确认平台服务范围，例如是否先从教会主页、讲道和小组资料开始。
- 指定哪些内容属于公开发布，哪些内容只给会友或小组成员阅读。
- 指定内容审核责任人，确保公开页面的神学、行政与对外信息一致。

### 4.2 网站维护同工

适合负责：

- 建立页面。
- 协助整理文字与图片。
- 维护页面结构、顺序与连结。
- 协助把草稿内容发布为公开页面或群组页面。

### 4.3 小组长、区长、事工负责人

适合负责：

- 管理所属群组成员。
- 维护本群组相关页面与活动资讯。
- 审核群组加入申请与活动报名信息。

## 5. 网站内容编制说明

本节是给内容编写与网站维护同工的实际操作原则。重点不是“技术开发”，而是“怎样把教会内容整理成适合网站阅读的页面”。

### 5.1 先决定页面属于哪一类

在编写前，先判断页面的性质：

- 全站页面：例如教会简介、聚会时间、牧养理念、受洗说明、奉献说明、课程总览、讲道入口。
- 群组页面：例如某个小组介绍、某事工说明、内部训练资料、活动须知。

如果内容是给所有人看，通常应规划为公开页面。
如果内容只给已加入某小组或某服事团队阅读，通常应规划为群组页面。

### 5.2 先决定可见范围

每一页在发布前，都应先确认可见范围：

- `Draft`：内容尚未完成、仍在审核、或只想内部预览时使用。
- `Group`：给该群组成员阅读，例如组内通知、服事流程、培训资料。
- `Public`：给全教会或外部访客阅读，例如主日信息、教会介绍、公开课程。

建议流程是：

1. 先存成 `Draft`。
2. 经内容负责人检查后，再改为 `Group` 或 `Public`。
3. 若页面未来需要长期维护，保留固定负责人。

### 5.3 标题与摘要要同时考虑中英文

系统支持中英文双语标题与摘要。即使目前主要使用中文，也建议保留英文栏位的规划，原因如下：

- 方便未来服务双语会众。
- 方便国际访客或新朋友理解页面主题。
- 方便后续扩展英文版页面内容。

建议写法：

- 中文标题：清楚、正式、符合教会用语。
- 英文标题：简洁、准确，不必逐字直译。
- 中文摘要：用 1 至 3 句说明页面目的。
- 英文摘要：维持相同信息重点，不必追求字数完全一致。

### 5.4 页面内容建议采用区块式编写

页面不是一次放上一大段文字，而是按阅读需要拆成几个区块。建议一个页面常见包含以下部分：

1. 页面开头：标题、简短说明、必要时附上一张主图。
2. 核心说明：介绍聚会对象、课程目标、报名资格、服事内容或参加方式。
3. 行动信息：时间、地点、联络方式、报名入口、相关连结。
4. 延伸资源：相关页面、讲道、课程或小组连结。

对阅读者来说，这比长篇未分段文字更清楚；对维护同工来说，也更容易局部更新。

### 5.5 内容编写原则

建议遵守以下原则：

- 一页只讲一个主题，不要把多个不相关事项塞在同一页。
- 先写结论，再写说明，不要让读者找不到重点。
- 把时间、地点、对象、报名方式写完整。
- 若页面会长期存在，避免写死很快过期的细节；可把变动性高的信息放在单独区块，方便以后替换。
- 若使用图片，优先选清楚、稳定、与教会场景一致的图片。
- 若引用影片或外部连结，发布前先检查能否正常打开。

### 5.6 适合教会网站的内容模板

以下是常见页面可采用的编制模板：

#### 教会介绍页

- 教会简介
- 聚会时间与地点
- 牧养异象或核心价值
- 初次来访须知
- 联络方式

#### 小组介绍页

- 小组名称
- 对象与年龄层
- 聚会时间与形式
- 带领同工
- 加入方式

#### 课程或活动页

- 活动名称
- 适合对象
- 时间地点
- 报名方式
- 注意事项
- 后续联络窗口

#### 讲道或信息入口页

- 系列主题
- 最新讲道
- 历史讲道入口
- 相关灵修或延伸阅读

### 5.7 内容审核建议

在页面公开前，至少检查以下项目：

- 标题是否清楚。
- 摘要是否能让第一次来访者看懂。
- 图片是否合适，尺寸与内容是否得体。
- 连结是否正确。
- 时间地点是否最新。
- 可见性是否设对，避免把内部资料误设为公开。
- 若有英文内容，是否足够自然易懂。

### 5.8 页面更新建议

建议教会建立固定更新节奏：

- 每周：检查首页、主日信息、近期活动。
- 每月：检查聚会时间、课程资讯、各事工页面。
- 每季：检查教会介绍、同工名单、常见问题与报名入口。
- 每次大型活动前后：新增活动页、更新报名说明、活动后整理回顾内容。

## 6. 对执事会的建议

若从治理与使用角度看，Alife 最适合作为“教会统一内容与群组协作平台”，而不是只做一个静态官网。执事会可优先考虑以下几项：

1. 哪些页面必须长期公开且定期更新。
2. 哪些群组或事工先纳入系统试运行。
3. 谁负责内容审核，谁负责技术维护，谁负责日常更新。
4. 哪些资料只开放给群组成员，哪些可以公开对外。

如果这些责任边界先定义清楚，平台上线后的维护会轻省很多。

## 7. 对网站维护同工的建议

1. 先帮助教会建立少量但稳定的核心页面，不必一开始做得很大。
2. 优先整理最常被询问的信息，例如聚会时间、地点、教会简介、讲道入口、课程与活动报名。
3. 所有页面都先走草稿，再公开。
4. 建议建立一份内部内容清单，记录每一页的负责人、最后更新时间与下次检查日期。
5. 若页面涉及活动报名、群组成员或内部资料，发布前务必再次确认可见性设置。

## 8. 总结

Alife 适合用来承载教会的日常运作信息、小组管理和内容发布工作。它的价值不只在于“把资讯放上网站”，更在于让教会用一致的流程来处理成员、页面、活动和讲道资料。

对执事会来说，它是一个可支持治理与协作的平台。
对网站维护同工来说，它是一个以页面和区块为基础、适合持续更新的内容工具。

如果教会按“草稿、审核、发布、定期更新”的方式使用，平台会比传统零散网页更容易长期维护。
