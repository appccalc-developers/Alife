RUNTIME ARCHITECTURE

Each layer owns one kind of truth.

Select a boundary to see what it owns—and what it deliberately does not. These separations are the basis for privacy, caching, compatibility and recovery.

alife / runtime map
SELECTED BOUNDARY

React bilingual PWA

React 19, TypeScript, Vite and React Router deliver public, member, leader and administration workspaces. TanStack Query/React DB and IndexedDB coordinate client data; the browser performs WebAuthn ceremonies, but final authorization remains server-side.

Never trust frontend role checks; never replay API responses from the PWA runtime cache.

CURRENT CAPABILITY SET

From finding a church to owning real work.

ALIFE does not pile features onto one screen. It organizes the experience around public access, member participation, content governance and ministry responsibility.

IDENTITY

Identity and entry

Passkey-first sign-in, HttpOnly JWT sessions, activation, invitations, public applications, group QR entry, browser continuation and recovery; LINE is a compatibility path and internal Alpha access is controlled testing only.

COMMUNITY

Church and group life

Hierarchical groups, membership and roles, announcements, albums, forums, contacts, notifications, visitor requests, sermons, Sunday bulletins, Bible progress and personal work.

PUBLISHING

Bilingual content governance

Groups own structured Page/Section content; working, submitted and published copies evolve independently. Reviewers can revise, approve or return a submission without mutating the working page or existing public snapshot.

ASSISTANCE

Bounded AI assistance

AI can assist with Event details, task and registration forms, RAM candidates, enrolment/review sessions, bilingual translation and poster drafts; it cannot confirm facts, grant authority, approve Packages or auto-publish.

Publishing is not a save button

three-copy publication model
  1. WORKINGGroup working copyContent teams keep editing; visitor content does not change directly.
  2. SUBMITTEDIsolated review copyReviewers revise, approve or return it; optimistic concurrency protects writes.
  3. PUBLISHEDApproved public snapshotSafe for public delivery and shared cache; remains live when a newer submission is returned.

EVENT DOMAIN

An Event is facts, capabilities and accountability—not a CRUD row.

Human acceptance creates an immutable Event Plan; Series owns recurrence, Occurrence owns one delivery, and a Package binds approval to exact source versions. Existing GroupEvent and version-0 semantics remain compatible.

SECURITY, PRIVACY AND CACHE

Cache follows audience. Authority follows current facts.

ALIFE does not cache by URL alone. Every response is first classified as public, group-shared, role-restricted or user-specific, then given the appropriate key, ETag, invalidation and no-store behavior.

PUBLIC
Public projection
Reviewed pages, sermons and public Events may enter shared edge cache with explicit keys, tags, TTLs and invalidation paths.
GROUP
Group-shared
Group pages, subgroups, Events and member lists are reused only after current authorization and visibility checks.
RESTRICTED
Role-restricted
Event-team, RAM, safeguarding, finance and approval evidence stay private/no-store and never share viewer ETags.
PERSONAL
User-specific
Identity ceremonies, applications, /api/me, notifications and personal work are no-store and never replayed by the PWA runtime cache.
SERVER

Server authorization

Sensitive operations check ownership, membership, role, purpose, version and platform permission.

IDENTITY

Minimal identity

JWTs carry minimal session facts; secrets are HMAC-protected and diagnostics exclude credential material.

CONCURRENCY

Versions and conflicts

ETag/If-Match prevents silent lost updates in versioned state; unknown values fail closed.

AI

Human accountability

AI proposes candidates; facts, roles, policy, approval and publication remain attributable human actions.
