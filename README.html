为什么是 Alife

不是更多工具，而是一条连续的参与旅程。

海外华人教会的网页、群组、活动和沟通常常散落在不同系统。Alife 以真实角色的下一步为组织方式，让人不用先理解系统，就知道自己现在可以做什么。

  1. 01

    发现教会

    公开首页、到访信息、讲道与历史文章，让第一次接触有清楚入口。

  2. 02

    进入群体

    通过 LINE 或成员账号登录，发现群组并完成申请、邀请与审批。

  3. 03

    持续参与

    活动报名、通知、论坛、相册、讲道和圣经阅读汇聚在移动端。

  4. 04

    带领与关怀

    组长管理成员、角色、子群组、公告、联系人、页面与活动。

  5. 05

    审核与发布

    双语页面先建立、预览和审核，再安全进入公开网站。

系统架构

快在边缘，规则留在后端。

Alife 以边界换取稳定：前端负责体验，Cloudflare 负责加速和短期会话，.NET API 负责授权与业务规则，SQL 保存持久事实。

共享缓存只保存同一授权范围内完全相同的内容；成员私有数据不会进入公开共享缓存。

  • React 19
  • TypeScript
  • Vite PWA
  • TanStack
  • .NET 10
  • Azure Functions
  • EF Core
  • SQL Server
  • Cloudflare Workers
  • Durable Objects
  • R2

不可退让的边界

服务增长，也守住信任。

教会社区的软件既处理公开内容，也处理成员身份、联系信息与小组关系。产品价值必须和责任边界一起交付。

授权实时可靠
JWT 只保存最小身份；群组角色与可见性依据当前后端数据检查，权限变化不等待令牌过期。
缓存服从隐私
公开、群组共享、成员专属与浏览器本地缓存各自有明确键、失效与可见性规则。
双语是数据结构
内容以 { en, zh } 形态保存；语言切换只改变呈现，不重取数据，也不破坏另一种语言。
AI 提议，人来决定
AI 可以形成策划、翻译与风险草稿，但不能编造安全事实，也不能绕过人工确认直接发布。

开始开发

一条命令，启动日常本地栈。

默认脚本启动 Azure Functions API、Cloudflare speed layer 与 Vite 前端。SQL Server 容器已运行时使用 SkipSql；需要刷新架构或种子数据时再应用迁移。

  • .NET SDK 10.0.x
  • Node.js 20+
  • Docker Desktop（本地 SQL Server）
  • Wrangler CLI 或项目内 npx wrangler
日常本地开发 
.\alife-dev.cmd -SkipSql
迁移与种子数据需要刷新时 
.\alife-dev.cmd -SkipSql -ApplyMigrations
